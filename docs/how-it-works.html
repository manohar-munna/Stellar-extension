How Stellar works

A Chrome extension that does tasks on web pages for you, while your private data stays on your device. The cloud model only ever sees a redacted screenshot with labels like [EMAIL_01], never the values. (SIH 2026 · PS 26171 · Team STELLAR_6)

One step of a task

1 Capturescreenshot + tag every button / field
2 Detectfind emails, IDs, keys, faces
3 Redactblur faces, black out secrets, label the rest
4 Sendsanitized frame + leak check
5 ReasonGemini picks one action
6 Validatelocal rules approve or block
7 Executeclick / type, real values filled in locally

on device cloud, sanitized only  In Local-first mode a small on-device model decides simple steps (filling known fields, submitting the form it filled) before redaction, so nothing is sent at all. Only uncertain steps go through Detect → Redact → Gemini, and Gemini also checks the finished page.

Why it is safe

  • No network request before redaction. Detection runs on the device; the outgoing text is scanned for any known private value (a leak check) before it is sent.
  • Semantic tags, not values. The model types [VAULT_EMAIL]; Stellar swaps in the real email locally, after validation.
  • A local gate on every action. Only allowed action types run, and only on real elements. There's a loop guard and approvals for risky clicks. Pasting an on-page secret into an ordinary field is blocked, and tags never go into URLs.
  • Page text is treated as data. Instructions planted on a page can't make Stellar leak a secret.
  • CAPTCHAs are never solved. Stellar pauses, you tick the box, and it carries on by itself.

Stack — and why each piece works

PieceWhat it isWhy it works
Extension shellChrome MV3: side panel, content script, captureVisibleTabSees exactly what you see in your own signed-in browser. Each element gets a stable tag (Set-of-Marks), so the model picks BUTTON_05 rather than guessing pixels.
PII detectionDOM rules: regex, Luhn check, Aadhaar/PAN/IFSC/UPI patterns, field types, vault valuesDeterministic, instant, offline. Field types catch passwords and card numbers even when the page hides their text.
Face detectionMediaPipe BlazeFace (WASM)Runs in about 10 ms on the device. It zooms into every image, so small avatars get blurred too.
RedactionCanvas: blur faces, black out credentials, mask PII with a tagThe model still knows what was there (an email, a password) and can reason about it, without the value.
On-device modelFastVLM-0.5B · Transformers.js · ONNX Runtime on WebGPUAbout 1 s per decision on a laptop GPU, cached after one download. It makes Local-first and fully offline mode possible, and unloads itself when idle.
Cloud modelGemini REST with JSON output, key rotation and model fallbackStrong reasoning for links, menus, reading pages and the final check. It only ever gets sanitized frames.
Real inputchrome.debugger mouse and keyboardTrusted clicks and typing work on React fields, code editors (Monaco and CodeMirror, via their API or a paste), custom dropdowns and autofilled logins.
Private vaultLocal key=value store; import from images, PDF, .docx, .vcf (pdf.js, on-device OCR)Forms get filled from your data without the AI seeing it. A missing required detail is asked once, then saved.
Panel stateIndexedDB (browser storage) inside the extensionTasks survive closing the panel. Unredacted captures are never written to disk.
